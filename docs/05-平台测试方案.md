## A. 测试目标、范围与不测清单

### A.1 测试目标

1. 验证系统 **10 项核心能力**：文档资产解析 → 清洗去噪 → 切块 → 向量索引 → 检索 → 提示词与工具 → LLM/MockLLM 调用与解析 → 指标校验 → 统一输出 → REST API/WebSocket 入口。
2. 验证输出的 **结构化 JSON** 符合统一规范（`answer/citations/used_metrics/confidence/notes`），`citations` 格式为 `[{type}:{id}:chunk_{index}]`。
3. 验证系统在 **CPU/离线/不可联网/不可微调** 条件下，能端到端稳定运行（使用 `FakeListChatModel` + `FakeEmbeddings`）。
4. 验证指标校验链（extract → 对齐 ES 实际指标 → ±5% 容差 → notes/confidence 调整）正确执行。

### A.2 测试范围

**数据类型**：
- 文档资产：docx（方案文档/SLA 文档）、xlsx（环境清单/交易清单）、pdf（架构文档）
- 压测指标：ES 中 run_no 对应的实际指标（tps/p95_ms/error_rate）
- 评测集：`data/dev_set.jsonl`（对话式场景操作样例）

**模型**：`FakeListChatModel`（离线 Mock），CPU 单机执行；可选 `ChatOpenAI` 对接智谱/阿里。

**核心流程**：`Loader → Cleaner(RunnableLambda) → Chunker(RecursiveCharacterTextSplitter) → Embeddings → VectorStore(Qdrant) → Retriever → ChatPromptTemplate + Tools → ChatModel(Agent) → JsonOutputParser → Guardrail → REST/WS`

**不可联网/不可微调/仅 CPU**：写入"范围与约束"，在异常与性能用例中体现（TC-NFR-301/302 验证离线降级）。

### A.3 不测清单

- 不涉及真实商用 LLM 联网调用的性能压测（仅 Mock）。
- 不测大规模分布式集群部署性能（Qdrant 单容器）。
- 不测前端 UI 可视化交互（仅测 REST/WS 接口）。
- 不测微调相关功能（禁止微调）。
- 不测已有性能测试平台核心模块（脚本/场景/运行），仅测 LLM 接入层与已有接口的集成。

### B.1 环境配置

| 类别 | 配置 |

| 限制 | 🔒 **禁网、仅 CPU 执行、不可微调** |

**环境初始化命令**：

```bash
# 启动依赖
docker compose up -d qdrant minio mysql elasticsearch

# 安装依赖
pip install langchain langchain-community langchain-openai langchain-qdrant \
    langchain-text-splitters python-docx openpyxl pypdf qdrant-client

# 初始化数据库
alembic upgrade head

# 启动 Master
uvicorn master.app.main:app --host 0.0.0.0 --port 8000
```

**禁网策略**：容器网络不映射公网出口；未配置 `LLM_API_KEY`/`EMBEDDING_API_KEY` 时自动降级为 Mock 组件。

## C. 测试策略与覆盖

### C.1 层级策略

| 层级 | 范围 | 回归频率 |
| --- | --- | --- |
| 单元 | Loader/Cleaner/Chunker/Embeddings/Guardrail 纯函数 | 每次提交 |
| 组件 | VectorStore+Retriever、PromptTemplate+Tools、ChatModel+Parser | 每次需求变更 |
| 集成 | 检索→Prompt→Agent→解析→Guardrail 全链路 | 每日 |
| E2E | REST API 对话 + WS 流式 + 报告生成 | 每周 |
| 回归 | P0/P1 缺陷修复后全量回归 | 缺陷修复后 |

### C.2 覆盖设计

**正向/反向/边界均衡**：
- 正向：解析成功、检索命中、工具调用成功、指标一致
- 反向：解析失败、空检索、JSON 解析失败、指标不一致
- 边界：BM25 开关（开/关）、Top-k 变化（1/5/20）、Chunk 大小（500/1000）、空 citations

**BM25 混检对比**（TC-RET-008）：
- 关闭 BM25：仅向量检索，记录命中率
- 开启 BM25：`EnsembleRetriever` 合并，记录命中率与去重后条数
- 断言：开启后去重条数 ≤ Top-k，命中率不劣化

### C.3 数据充分性

- 文档资产：5 种资产类型各 1 份，覆盖全部 Loader 路径
- dev_set.jsonl：20 条全量跑，覆盖 8 个工具的调用
- ES 指标：run_no=1001 含 tps/p95_ms/error_rate 三项
- xlsx 列映射：覆盖 ENV_INVENTORY_COLUMN_MAP / TXN_INVENTORY_COLUMN_MAP 全部列

### C.4 输出规范检查（独立用例）

TC-OUT-011 独立校验：
- JSON 含 `answer/citations/used_metrics?/confidence/notes` 字段
- `citations` 格式符合 `[{type}:{id}:chunk_{index}]`
- `confidence` ∈ [0, 1]
- 无 `citations` 时返回兜底引用（检索 Top-1），不允许空 citations 的成功结果

### C.5 指标校验链（独立验证）

TC-VAL-012 / TC-ERR-105 独立验证：
- extract：从 answer 中正则抽取 tps/p95_ms/error_rate
- 对齐：与 ES 中 run_no=1001 的实际指标比对
- ±5% 容差：`METRIC_TOLERANCE=0.05`
- 调整：不一致 → notes 写 "Mismatch with actual metrics: {field}"，confidence ≤ 0.7

## D. 通过/退出准则与量化阈值

| 维度 | 阈值 | 说明 |
| --- | --- | --- |
| 可运行性 | E2E 跑通率 100%，无致命异常 | 样例数据端到端无 5xx |
| 检索相关性 | Top-5 命中率 ≥ 80% | 含正确证据段比例 |
| 回答完整性 | JSON 字段完整率 100%，citations 非空 | 5 字段齐全 |
| 引用准确性 | citations 格式合规率 100% | `[{type}:{id}:chunk_{index}]` |
| 指标校验正确性 | ±5% 内一致率 ≥ 95%，不一致降 confidence 并写 notes | Guardrail 验证 |
| 异常鲁棒性 | 异常用例通过率 ≥ 95% | 8 条异常用例 |
| 离线降级 | 未配置 API Key 时端到端可跑通 | FakeEmbeddings + FakeListChatModel |
| 性能 | 样例端到端 ≤ 30s（Mock），检索 ≤ 2s | CPU 单机 |

**退出准则**：上述全部阈值达成；P0 缺陷清零；P1 缺陷 ≤ 2 且有规避方案。

## H. 风险、优先级与回归策略

### H.1 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| docx/pdf 解析不稳 | 文本质量差 | 使用 LangChain 官方 Loader，异常时 status=failed + retry-parse |
| xlsx 表头不规范 | 结构化抽取失败 | unmatched_columns 记录，D5 remap 接口修正 |
| Qdrant 索引损坏 | 检索失败 | 自动重建（删 collection + 重新 upsert），日志报警 |
| Mock 与真实 LLM 差异 | 生产行为不一致 | `get_llm()` 工厂隔离，Mock 响应覆盖正常/异常路径 |
| 长上下文截断 | 回答缺信息 | context 1800 字符限制 + 日志记录裁剪 |
| 指标单位不明 | 校验误判 | notes 标注 "unit unclear"，confidence 降至 0.6 |

### H.2 优先级

- **P0**：可运行性（端到端跑通）、结构化输出（5 字段齐全）、引用准确性（格式合规）、指标校验（±5% 容差）
- **P1**：BM25 混检质量、检索命中率、工具链编排正确性
- **P2**：性能优化、日志粒度细化

### H.3 回归策略

- P0/P1 缺陷修复后必须回归验证（关联用例全量重跑）
- 每次需求变更后运行 dev_set.jsonl 全量评测，对比修复前后命中率与平均 confidence
- 回归结果写入 `results/regression_{date}.json`
